## 2. Architecture overview

A **static site generated by a small bespoke Python generator**. No framework, no Node toolchain, no runtime dependencies.

```
src/data/*.json  ──┐
src/templates/*.html ├──> build.py + pages.py ──> dist/  ──> Netlify
src/images/*     ──┘        (Python 3 + Pillow)
```

- **`build.py`** — helpers, template engine, image pipeline, schema generators, sitemap, redirects, zip packaging.
- **`pages.py`** — every page's structure and copy. Imports `build` and calls `write_page()` per page.
- **The two share one module instance.** `build.py`'s `main()` aliases itself into `sys.modules["build"]` before importing `pages`. **Do not "fix" this into a plain import** — it would create a second module copy and break the `PAGES` list that builds `sitemap.xml`.

**Template engine** (~40 lines in `build.py`):
- `{{ key }}` — escaped substitution
- `{{{ key }}}` — raw substitution (pre-built HTML)
- `{{> partial }}` — includes `src/templates/_partial.html`

## 4. Important design decisions

**Positioning: "One car a day."** Ash books one vehicle per day. It's true, verifiable, defensible against every Kent competitor, and it justifies her price. Everything else (female-owned, award-winning, 29 × 5★) is evidence for it, not a competing headline.

**No price may be hard-coded in a template.** Everything comes from `pricing.json`. This exists because the original site published Premium Exterior at £120 on one page and £140 in the store — the same number in two places drifted and was quoting customers wrong.

**Booking order was deliberately changed.** The old site took **full payment before any date existed** ("once you have paid, I will be in contact to arrange a date"). The new flow is: enquire → Ash confirms the date → 20% deposit. The client was told and agreed. If asked to revert, push back once — it's likely the single biggest conversion improvement.

**No durations anywhere.** The client explicitly asked for all "3–12 hours" style copy to be removed as off-putting. Verified zero across all pages. **Do not reintroduce.**

**Names on reviews are minimised** to first name + surname initial. Two reviews were trimmed because reviewers disclosed a health condition and a wheelchair-accessible vehicle — special-category data under UK GDPR. Praise quoted, sensitive detail not. No wording was altered.

**Number plates are redacted at build time** via `redactions.json` — blurred before any derivative is generated, source files untouched.

**Per-area pages were deleted.** There were nine (`/areas/canterbury/` etc.). The client judged them filler; only `/areas/` remains.

**System-font era is over** — Archivo variable is self-hosted (34 KB, latin subset, OFL). No third-party font requests.

**Mobile navigation must never depend on JavaScript.** The burger is a `<label>` bound to a hidden checkbox; CSS drives the menu. This was a real bug once — a JS-only menu left phones with no navigation at all. Verified by deleting `main.js` and confirming the menu still opens.

## 6. Build and deployment process

```bash
python3 build.py                     # build to dist/          (~3s incremental)
python3 build.py --clean             # wipe and rebuild        (~32s, regenerates 163 images)
python3 build.py --serve             # build then serve :8000
python3 build.py --preview           # share-safe build: noindex + gold banner
python3 build.py --zip               # package dist/ for Netlify drag-and-drop
```

Or double-click **`Preview site.command`** — rebuilds, serves on :8765, opens the browser.

**`dist/` is committed on purpose.** `netlify.toml` sets `publish = "dist"` with an echo for a build command, so Netlify needs no Python or Pillow and a deploy cannot fail on a dependency. **The consequence: you must run `python3 build.py` and commit `dist/` before pushing, or the live site won't reflect your source changes.** Swapping to a Netlify-side build is one line in `netlify.toml` and is documented there.

**Zips upload far more reliably than folders.** Dragging the `dist` *folder* onto Netlify Drop routinely loses nested directories — the symptom is a working homepage where every link 404s. Always drag the **zip**.

## 9. FormSubmit — where it is configured

**One place only:**

- **Value:** `src/data/site.json` → `"formEndpoint": "https://formsubmit.co/ashs_vvad_ltd@icloud.com"`
- **Used at:** `pages.py` line ~616 — `<form class="form" id="bookform" method="post" action="{SITE['formEndpoint']}">`

The form posts `_subject`, `_template=table`, and a `_honey` honeypot field. Client-side validation is in `main.js`; the form still submits without JS.

🔴 **IT IS NOT ACTIVATED.** FormSubmit requires a one-time activation email before it delivers anything. Until that's done **enquiries are accepted and silently discarded.** This is the single biggest launch blocker.

**To activate:** submit the live form once → FormSubmit emails `ashs_vvad_ltd@icloud.com` with a confirmation link → Ash clicks it → submit again to verify. **Check junk — the activation mail lands there often, and only sends on the first submission.**

**Recommended alternative:** since the site is on Netlify, **Netlify Forms** removes the third party entirely — no activation, submissions stored in the dashboard *and* emailed. It needs one attribute plus a hidden field. Offered to the client; not yet chosen.

## 15. Coding conventions and patterns

**Data, never templates.** Adding content means adding to `src/data/*.json`. Templates read; they never define. A price appearing in a template is a bug.

**Progressive enhancement, strictly.** Every page must work with `main.js` blocked. Reveal animations are gated behind a `.js` class set by an inline head script, so a failed JS load never leaves content invisible. **Test this by deleting `dist/main.js` and reloading.**

**British English throughout.** Colour, optimise, realise, £ with no decimals (`£100`, not `£100.00`).

**Voice:** first person (it is one person), plain, specific, confident. Numbers over adjectives. Never apologise for the price — explain it once and move on.

**CSS:** one file, custom-property tokens at the top, BEM-ish naming (`.card__media`, `.tier--pop`). All motion behind `@media (prefers-reduced-motion: reduce)`. Watch specificity — a generic `span` rule once beat `.stars` and stacked five stars vertically.

**Images:** always through `picture()` / `cropped()` / `ba_image()`. Never upscale past source width. `loading="lazy"` + `decoding="async"` below the fold; `fetchpriority="high"` on the hero only. Always `width`/`height` for CLS.

**Accessibility is not optional.** One `<h1>` per page, no heading skips, ≥44px tap targets, WCAG AA contrast (compute it — don't eyeball), `aria-hidden` on decorative elements.

**Verify, don't assume.** Every claim in this project has been checked with a script or a browser measurement. Say what was verified and how.
